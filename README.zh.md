# AxMem — 面向 Claude Code 的记忆治理层

**为 AI coding agent(首先是 Claude Code)提供确定性护栏。**

> **教训要变成闸门。** 别的记忆产品卖的是"召回更准"；AxMem 卖的是另一件事:
> **同一个错误不会犯第二次。**

长期运行的 agent 记忆系统有两个会互相放大的问题:(1) 写下的教训不等于**被强制执行**的
教训——除非有一个 hook 能真的拒绝会重犯这个错误的工具调用,否则没有任何东西能拦住它
重演;(2) 会持续膨胀的记忆文件会腐化——悬空指针、体积膨胀、孤儿块、内容重复——而且
往往要等人发现才会处理。AxMem 是一个 Claude Code 原生、本地优先、可被 git 审计的
**记忆治理层**,用机械检查而不是更多说明文字来同时解决这两个问题。它不取代你的记忆
文件,而是围绕它们加上确定性的检查机制。完整的功能表、架构图、安装/自测/隔离纪律
说明请见英文版 [README.md](README.md)(本仓库以英文为主,长期维护也在英文版进行)。

## 核心支柱(摘要)

- **写入纪律闸门**:原子条目、索引↔条目一致、孤儿检测、体积上限(带 `[sole-record]`
  保真豁免)——由 hook 强制,而非文字约定。
- **指针完整性**:每个 `→pointer` 与 `[[wiki-link]]` 必须能解析;只有当细节在别处仍然
  存活时,压缩才合法。
- **守卫金丝雀**:每个守卫定期喂已知输入自证仍在生效;一个证明不了自己还在拦的守卫会
  被大声退役——静默死亡是守卫的头号杀手。
- **冗余检测**:四个可计数代理指标(条目内重复、语料重复、填充词、gzip 压缩比),不判断
  语义,只判断"这是不是在自我重复"。
- **守卫代码指纹**:守卫代码本身随 git 同步,sha256 名册能抓到未记录的守卫代码改动。
- **教训分类体系**:每条教训带一个来自受控词表的 `Class:` 行(`core/manifest.cjs`);
  编辑命中某个类触发词的文件时,会一并推送该类最新成员——"这是不是同一类错误"
  变成机器可判定的问题。
- **退役=移动**:删除一条记忆要求其原文在同一次提交里出现在归档文件中——丢失在结构上
  不可能发生。
- **融合检索**:精确文本通道与语义通道每次查询都同时跑;精确命中置顶,未命中记账而非
  被忽略。
- **派发守卫**:子代理的 model/effort 组合在派发前被检查——用 AST 解析 workflow 脚本,
  而不是猜正则。
- **Dream(月度卫生维护)**:每月一次、需人工批准、**只报计数**的维护提案。基于"判断"
  的自动改写被经验审计禁止(5/10 错误率),独立研究现称之为"记忆虚构"。
- **热度遥测**:访问日志驱动晋升/降级提案——靠证据,不靠感觉。

## AxMem Pro(即将推出)

因果影子记忆引擎——在每次编辑时计算"未来的强制执行 hook 本来会做什么",全程只记录、
不拦截、不注入的图分析层——不包含在这个 open-core 仓库中,将以 **AxMem Pro** 形式
按商业许可证发布,包含:

- **因果影子记忆**:基于图的记忆文件分析引擎,跟踪取代关系、cause/follow 链接与
  跨条目身份。
- **五维影子比较器**:在一次策略改动真正生效前,把它"本来会做的判断"与现有闸门
  的实际判断在五个独立维度上逐一对照。
- **回放(Replay)**:对已记录的会话按新版守卫做确定性回放,用真实历史验证一次
  策略改动,而不是靠猜。
- **检索基线**:融合精确文本与语义检索,配一套可复现打分的基线语料,用于调优
  召回精确率。
