**D11 的 Windows 结论：并发互斥层面成立，但须删除上述 60 秒例外。**

- Node 的 Windows `rename` 经 libuv 调用 `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING)`；Windows 明定目标为既存目录时失败。因此同卷、同父目录、owner 文件已关闭的两个 claim 中至多一个成功。[libuv 实现](https://github.com/libuv/libuv/blob/v1.x/src/win/fs.c#L2177-L2184)、[MoveFileExW 语义](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)、[Node `renameSync`](https://nodejs.org/api/fs.html#fsrenamesyncoldpath-newpath)
- 不应依赖具体错误码；任何 rename 错误都表示“未获锁”。跨卷在 sibling 临时目录设计下本应不可发生，句柄或权限错误应安全失败。
- 在正确的死亡判定下，不存在“持锁者与回收者都通过”的协议内交错：A 通过核对且仍能继续时，其 PID 与启动时间必然仍匹配，B 不能回收；A 已终止时则不可能恢复执行。风险只来自超时回收、把查询失败误判为死亡，或协议外修改。
- Windows 可行身份 API：`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` 后调用 `GetProcessTimes` 读取 creation `FILETIME`；它是64位、100ns单位，应存十进制字符串或 `BigInt`，不能转成 JS `Number`。[GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes)
- 无原生绑定时可用 PowerShell/.NET 的 `(Get-Process -Id $pid).StartTime.ToFileTimeUtc()`；但进程已退出、访问受限或命令超时必须判 **UNKNOWN**，不得判死。[Process.StartTime](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.starttime)
- 检查过且干净的面：恢复矩阵按 `phase × current` 已互斥；`COMMITTED + current=new` 与 `current≠new/缺失` 不再重叠，穷举脚本要求足以防止实现重新引入重叠。
